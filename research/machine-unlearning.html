When “forget this data” breaks the model

Machine unlearning removes the influence of some training examples without retraining from scratch. I studied a popular shortcut, NegGrad+, and found that it becomes unreliable when the examples to forget all come from the same class.

Goal

I try to show that NegGrad+ becomes unstable in BatchNorm networks when the set to forget is concentrated in a single class, whereas a stratified set of the same size causes no problem. Then I look for which part of BatchNorm is responsible, whether the NegGrad+ objective plays a role, and whether the problem can be fixed. The page follows the written report step by step; the interactive figures let you play with each idea.

What is settled

  • Concentrated deletion requests make NegGrad+ unstable in these BatchNorm networks; spread ones of the same size do not.
  • The effect needs normalisation by batch statistics: it disappears with BatchNorm frozen or with GroupNorm.
  • It goes beyond the difficulty of the classes involved, and it is far stronger under NegGrad+'s unbounded objective.
  • The fixes tried remove the instability, but mostly by forgetting less.

What is still open

  • The exact mechanism: BatchNorm is the main suspect, not a proven culprit.
  • Whether any method can forget a concentrated request as well as retraining does, without breaking the model.
  • Whether anything is truly erased: never measured beyond one exploratory attack.
  • How far it generalises beyond a small CNN on Fashion-MNIST.

1 · Experimental setup

1.1 Data and notation

  • Fashion-MNIST: 60,000 training images (28×28, greyscale, 10 classes). 5,000 are set aside for validation (500 per class), so |D| = 55,000. The 10,000 test images are used for evaluation only.
  • D_f: the set to forget, always 600 images. D_r = D \ D_f: the set to keep.
  • Concentrated (c0 to c9): the 600 images all come from one class, about 11% of it. The rest of the class stays in D_r: the model should forget these 600 boots, not the concept of a boot. Stratified: 60 images from each class.
  • Reference model R: retrained from scratch on D_r only, with the same recipe as O. It is what unlearning tries to approach without retraining.

Build a deletion request

1.2 Model and training of O

A small convolutional network: 3 blocks of 3×3 convolution (no bias) + BatchNorm + ReLU, with 32, 64 then 128 filters and two max-pooling layers, followed by two dense layers (256 then 10): about 1.7 M parameters and 3 BatchNorm layers. SGD, learning rate 0.05 with a cosine schedule, momentum 0.9, weight decay 5·10⁻⁴, 15 epochs, batches of 128, no augmentation: about 93% test accuracy. One O per seed.

The model outputs one raw score (logit) per class; the softmax turns them into probabilities, and the error on an image is the cross-entropy −log ptrue.

Try it: three classes

1.3 Weight initialisation

No custom initialisation was written: every model uses PyTorch's defaults (no nn.init or kaiming call in the notebooks), with the seed fixed right before the model is built, so the same seed gives the same starting weights bit for bit.

  • Convolutions and dense layers: weights drawn uniformly in ±1/√n, n being the number of inputs of the neuron, so Var(w) = 1/(3n). Convolutions have no bias; dense-layer biases are drawn in the same range.
  • BatchNorm: γ = 1, β = 0 (learned parameters); stored mean 0 and stored variance 1 (buffers).
  • Why the variance matters: if it grows from layer to layer, logits become huge (100% on one class, huge losses and gradients); if it shrinks, logits are all near 0 (about 10% per class, tiny gradients). Kaiming (He) uses Var(w) = 2/n to keep it constant through ReLUs; PyTorch's default is six times smaller.
  • Why it does not matter here: a BatchNorm follows every convolution and resets the scale to 1, so the shrinkage never accumulates. Same for the ResNet-18 of step 2, skip connections included.
  • Unlearning methods start from a copy of O; each R has its own initialisation seed.

1.4 BatchNorm

BatchNorm works per channel: for each channel it computes the mean μB and variance σ²B over all images of the batch and all positions (N×H×W values), then outputs y = γ·(x − μB)/√(σ²B + ε) + β.

γ and βStored mean and variance (“buffers”)
RoleRe-stretch and re-shift the normalised values.Normalise at evaluation time, when there is no batch.
How they changeLearned by gradient descent.Measured: after each training-mode batch, stored ← 0.9·stored + 0.1·batch statistic.
  • Training mode: normalise with the current batch's statistics; the gradient flows through μB and σ²B, and the buffers are updated.
  • Evaluation mode: normalise with the buffers, which no longer change: a fixed affine map per channel.
  • Recalibration: recompute the buffers exactly on all of D_r (true mean and variance), layer by layer, without touching any weight, γ or β; the images to forget are never used.

Illustration: the 16 values are made up to show the arithmetic; the real network has 32 to 128 channels per layer.

Why a one-class batch is special. During NegGrad+, a concentrated forget batch is normalised by its own unusual statistics, and the gradient flows through them. The forget batches also pull the stored statistics towards one class, so a model evaluated with them can look broken.

1.5 Number formats

All training runs in FP32; there is no half-precision training. On the A100, PyTorch runs convolutions in TF32 by default (rounding to about 3 significant digits inside multiplications), hence check tolerances of 10⁻⁵ per layer and 10⁻⁴ relative on the network. Sensitive checks run in FP64. FP16 was only used to store some descriptive measures in step 3 (an overflow above 65,504 was fixed by a dated amendment).

1.6 NegGrad+ and the unlearning procedure

NegGrad+ minimises L = α·CEr − (1−α)·CEf: the loss goes down on D_r and up on D_f. Since CE = −log p has no ceiling, nothing stops the push.

Push the probability of the true class down

As p goes to 0, −log p grows without limit: nothing stops the push. In the experiments, a forget loss above 10 counts as a divergence. A control method that instead teaches random wrong labels has a finite target and cannot run away in the same way.

  • One epoch over D_r = 425 steps; at each step a batch of 128 images from D_r and 64 from D_f (successive permutations of D_f, each image seen about 45 times).
  • SGD, constant learning rate 0.01, momentum 0.9, weight decay 5·10⁻⁴; forget weight 1−α ∈ {0.001, 0.01, 0.05}, 0.01 as the main value.
  • The global gradient norm is clipped at 5: a safety belt against huge steps when CEf runs away.

1.8 How we judge forgetting

Forgetting can never be checked directly: a model has forgotten D_f if it cannot be told apart from R. And forgetting does not mean being wrong: on concentrated sets, R still recognises about 93% of the images to forget, because it learned the class from the other images. A model far below that does too much, which is also detectable. Three yardsticks are used, always with recalibrated buffers:

  • accuracy on D_f compared with R: above R the model does not do enough; far below, it breaks;
  • forgetting strength E = mean over D_f of log₁₀ pO(y|x) − log₁₀ pmodel(y|x): how much the confidence in the true class dropped, in decades; ER is the same for R;
  • a membership-inference attack (once, exploratory, on Tiny ImageNet): AUC 0.5 means the attacker cannot tell.

These check that a method that does not break still does something. Nothing on this page claims that a model has erased D_f.

3 · Step 2: replication with statistical tests

New models, a protocol written before running, 1,141 units in 6 h on an A100, 9,801 checks passed.

  • Study 1: Fashion-MNIST, BatchNorm CNN, variants A and C, 5 seeds. Per seed: 11 forget sets, each with an R, a fine-tuning run and NegGrad+ under A and C at 3 weights (66 NegGrad+ runs per seed, 330 in all).

3.1 The statistic U

Each concentrated run is compared with the paired stratified run (same seed, variant, weight and O): ψ = 1 if it is more unstable (higher Smean), 0.5 if tied, 0 otherwise; a numerical failure always counts as more unstable (none occurred). Us = mean of ψ over 10 classes × 3 weights = 30 comparisons for seed s. U = 0.5: no effect; U = 1: always more unstable.

  • Why per seed: the 11 runs of a seed share the same O, so they are not independent; counting them separately would fake precision. One U per seed, then a t test over seeds.
  • p-value: the probability of a result at least as extreme if there were no effect, not the probability that the result is due to chance.
  • pHolm: with several tests, the risk that one “succeeds” by luck grows (about 40% with 10 tests at 5%). Holm adjusts the p-values to keep that overall risk at 5%.
  • TOST: “no difference detected” is not “no effect”. The TOST shows that the mean loss gap concentrated − stratified (Δmean, in decades) lies within a margin of ±1 decade (90% interval).

Try these statistics on real numbers: the 12 per-seed penalties of the tuning study (step 6). Change how many seeds are used and watch the interval, the p-value and the equivalence test move.

Mean = average of the seeds. SD = how much seeds differ. Standard error SE = SD/√n, the uncertainty of the mean. The 95% confidence interval (CI) is mean ± t × SE, where t comes from Student's distribution with n−1 degrees of freedom. The t-statistic = mean / SE; the p-value is the chance of a t at least that large if the true penalty were 0. Equivalence (TOST): the 90% interval must lie inside a margin fixed in advance (±2 points). A result can be both “detected” (CI excludes 0) and “equivalent” (inside the margin): a real but small effect. (The values are rounded to 2 decimals here, so t may differ from the frozen analysis, 11.95, in the last digit.)

5 · Step 4: concentration or hard classes?

So far the same six classes always failed. Maybe “concentrated” just meant “contains a hard class”. This step separates the two.

Plan: 10 new seeds (401–410), each with a new O; variant A at 0.01, C as secondary. Per seed, 68 sets of 600 images: 10 pure sets, 45 pairs (300 + 300), 12 five-class sets (120 per class) and 1 stratified set, so 680 runs. Concentration is the label entropy H = log₂(number of classes): 0, 1, 2.32 or 3.32 bits.

Label entropy: how mixed is a forget set?

Measure: the early loss S = mean log₁₀ CEf over the first 24 steps, fixed in advance on earlier traces (no divergence before step 24; it already separated future divergers, AUC 0.92). It measures the cause before the blow-up, not the size of the blow-up.

Model: what would a mix give if only its classes mattered? Each class has an effect xc, and a mix with proportions pc is predicted by a power mean Mλ = (Σ pc xcλ)1/λ, with λ estimated between −3 and 3 rather than guessed. The model is S = log₁₀ Mλ(p; x) + γ·H + noise: γ = 0 if class identity explains everything, γ < 0 if spreading a request helps beyond its classes.

Power mean: many ways to combine two classes

Suppose class A alone gives an early forget loss of 1 and class B alone gives 9. What should a 50/50 mix give? It depends on how difficulties combine; the power mean Mλ = (½·1λ + ½·9λ)1/λ covers a whole family.

6 · Step 5: is it the NegGrad+ objective?

NegGrad+ is compared with random labels (RL): each image to forget gets a wrong label drawn among the 9 other classes, and the model is trained towards it: L = α·CEr + (1−α)·CE(xf, wrong label). Unlike NegGrad+, this loss has a floor. Take a boot to forget, labelled “sneaker” by RL:

NegGrad+ has no finish line: the loss keeps rising and the gradient keeps pushing (only clipping slows it). With RL, once an image is predicted “sneaker”, its term and gradient become tiny: the push dies out on its own. RL is “walk to the wall and stop”; NegGrad+ is “get as far from the wall as you can”. This does not mean p(sneaker) rises at every step: each step sees one batch of 64, steps have a finite size, and the keep term (99% of the loss) pulls back, since D_r holds other boots labelled “boot”. Everything else is identical (same O, sets, batches, BatchNorm treatment A, learning rate and clipping), so the objective is the only thing that changes.

6.1 First attempt: the clipping burden

B = share of the 425 steps where the gradient norm exceeds 5 and is clipped. Per method, Δ = Bconcentrated − Bstratified, and θB = ΔNegGrad+ − ΔRL = 0.30 [0.29, 0.32] (10 seeds, 782 runs): on concentrated sets NegGrad+ clips about 30% more steps than RL.

Floor effect. Under RL, B is stuck at 0 (4 clipped steps in 330 runs), concentrated or not. That does not prove RL is unaffected: a gradient norm going from 1 to 2 stays below 5, and B sees nothing, like a fever alarm that only rings above 40 °C. A continuous measure was needed.

7 · Step 6: remedies for the instability

7.1 How the damage is measured

U = accuracy of O on D_r − accuracy of the unlearned model on D_r, both recalibrated (damage in the weights, not buffer pollution). Penalty = mean U over the 10 concentrated sets − U of the stratified set, per seed. The effect of a remedy is I = penalty of plain NegGrad+ − penalty with the remedy.

A small penalty is not automatically good news. A model that forgets nothing damages nothing. So the forgetting strength and the accuracy on D_f are always checked alongside, against R (~93%).

7.2 Main remedy: per-condition tuning

Maybe NegGrad+ is not fragile and the default (learning rate 0.01, forget weight 0.01) is just bad for concentrated sets. 20 settings: lr ∈ {0.001, 0.003, 0.01, 0.03} × 1−α ∈ {0.001, 0.003, 0.01, 0.03, 0.05}, chosen per class on 3 tuning seeds (447–449) by a fixed rule:

  1. stable: no divergence or collapse on the 3 seeds;
  2. feasible: stable and strength E ≥ ER;
  3. among feasible settings, the best recalibrated validation accuracy;
  4. if none is feasible: among stable settings, the one that forgets the most.

Evaluation on 12 other seeds (450–461, chosen by power simulation), so that the choice is not judged on the seeds that made it; t test on the penalty and TOST with a ±2-point margin.

7.3 The other two remedies

  • Frozen target (bounded objective): for each image to forget, descend towards O's output with the true class removed and renormalised. 12 seeds (421–432): penalty reduced by 16.2 points [14.1, 18.4], 0 collapses vs 70/120. But it still recognises ~97% of the images to forget, and it reaches its target only in training mode, inside one-class batches: once recalibrated, the change is gone.
  • RD64 (BatchNorm): NegGrad+ kept, but the forget batch is normalised with the statistics of 64 images of the mixed keep batch, detached, without updating the buffers. 14 seeds (433–446): penalty reduced by 13.7 points [12.6, 14.7] in all 14 seeds; divergences 84/140 → 0/140. Three things change at once, so which one works is unknown.

Putting it together: is it real, and is it BatchNorm?

Two questions that the project always kept apart. Is the effect real, or chance? Statistically the answer is very clear. Is BatchNorm the cause? There the answer is more careful: every experiment points at it, but no study isolated a mechanism.

How a cause is shown in an experiment

A correlation is not enough. The method is the intervention: keep everything identical, change one thing, and see whether the effect disappears. If you change the bulb and the lamp lights up, the bulb was the problem; if you changed the bulb and the socket, you only know it was one of the two. The whole chain applies such interventions to BatchNorm on the same seeds, then checks statistically that the difference is not chance.

Why GroupNorm is the key control

GroupNorm does the same job as BatchNorm but on each image alone: a batch of 64 boots or a mixed batch makes no difference to it. If the problem came from NegGrad+ or from the classes alone, it should survive the swap; if it comes from normalising with batch statistics, it should vanish. It vanished, and TOST shows the remaining effect is equivalent to zero, whereas under A concentrated runs sat 2.39 decades (about 250×) higher.

What can be claimed

  • The effect is real: tiny p-values, present in every seed, reproduced on new models and on CIFAR-10.
  • It depends on normalising with batch statistics: it disappears with C, B and GroupNorm.
  • It comes from concentration, not only from which classes are involved.
  • It is much stronger with an unbounded objective than with a bounded one.

What cannot

  • The exact mechanism: most interventions change several things at once. The single-factor ones (A vs E1D, RD64 vs E1D) show partial contributions, not a full explanation.
  • So BatchNorm is the main suspect with a strong file, not a proven culprit.

8 · Limits and future work

Limits

  • True erasure is never measured: one exploratory membership-inference attack, on Tiny ImageNet (NegGrad+ AUC 0.39: an inversion, not erasure).
  • BatchNorm is the main suspect, but no mechanism was isolated: most variants change several things at once.
  • Mostly a small CNN on Fashion-MNIST, 3 to 14 seeds. On Tiny ImageNet the effect goes the same way but is much weaker (θ = 0.029 decade).
  • The studies share a data split, so they are not independent replications.

Next

  • Run the PCGrad study already frozen (never executed).
  • Replace BatchNorm with GroupNorm or LayerNorm across the whole chain.
  • Measure the forgetting of the remedies properly (membership inference, distance to R, several R per condition).
  • Predict risky deletion requests from batch statistics computed before unlearning.
If you deploy unlearning: look at the class composition of deletion requests, test methods on concentrated ones, report divergence, collapse, accuracy loss and forgetting strength separately, and do not assume tuning will save you.

Appendix · All 13 studies, in order

The project is a chain of 13 studies. Each one answered a question left open by the previous one. Open a study to see its question, its design, what came out and what it does not show. Filter by role or by status.

Post hoc: the analysis was decided after seeing data. Pre-specified: question, test and wording fixed and committed before the run. Exploratory: pre-specified, but with fewer seeds than the protocol itself requires for a firm claim.

01The original study (v3): a success for the wrong reasoncriterion fixed in advance · 5 seedsFashion-MNIST, CNN, concentrated vs random forget sets
Question
Does NegGrad+ “forget better” when the 600 examples to forget come from a single class, compared with a random set of the same size? The directional criterion was written down before the run.
Why this study
Starting point. Unlearning methods are usually tested on random forget sets; real deletion requests (one user's photos, one topic) are often concentrated, so the composition of the request deserved a direct test.
Design
A small BatchNorm CNN trained on 55,000 Fashion-MNIST images; fine-tuning and NegGrad+ compared with a model retrained without the forget set, over 5 seeds (1–5). Hyperparameters were tuned beforehand on seed 0, with a preservation rule (lose at most 1 point) and a forgetting-gap score. Decision rule: “supported” if the mean is positive, the 95% interval excludes 0 and all seeds agree; no correction for multiple tests.
Result
NegGrad+ passed formally (+54 points on the main criterion). But only through runs that collapsed: 26 of 55 runs ended at ≤ 20% test accuracy, all with concentrated forget sets (classes 1, 2, 4, 6 in every seed; 5 and 7 in some), none with the random set.
Two flaws found later
A model that always predicts the same class scored perfectly on the forgetting-gap score, so the tuning could pick settings that destroyed the model (the fallback was triggered for six classes, with settings losing 83 points). And the random set had been tuned at α = 0.95 but the concentrated sets at α = 0.99, a confound.
In plain words
The test said “forgetting works much better on concentrated sets”. In reality, on those sets the model was broken: it “forgot” the boots because it no longer knew anything. The question changed from “does it forget well?” to “why does it blow up, and only on concentrated sets?”
Does not show
Any forgetting. A model that recognises nothing “forgets” trivially. Accuracy was measured with the BatchNorm statistics left by unlearning, and no recalibrated evaluation exists for this study, so we cannot tell how much of the collapse was in the weights.
02Diagnostics 1–3: memory, weights, or the BatchNorm treatment?post hoc · 5 seedsWhich way of handling BatchNorm avoids the blow-up?
Question
The concentrated runs looked like an optimisation blow-up. Does it depend on how BatchNorm normalises the batch to forget?
Why this study
Study 01 “succeeded” with destroyed models. Before running any new study, the cause had to be located: was it the stored BatchNorm memory, the weights, or the way the forget batch goes through BatchNorm?
Design
Diagnostic 1: the 55 runs of v3 replayed bit for bit (same starting model, same batches, same order), changing only how the stored statistics are handled: momentum 0, no update by the forget batches (V1c), or exact recalibration afterwards (V2); plus a control with α = 1 (no forget term). Diagnostic 2: same model, weight 1−α = 0.01, 30 concentrated tasks (6 classes × 5 seeds). Implementation A (separate training-mode passes, the original) compared with B (retained and forgotten images in one batch) and C (BatchNorm frozen in evaluation mode). Diagnostic 3: variants of the forget pass on classes 1 and 8: E1 (running statistics of the retained data), E1-detached (own statistics, no gradient through them), E1-O (the original model's frozen statistics); 342 consistency checks. Reading criteria were dated before each computation, but the classes were chosen after v3.
Result
Diagnostic 1, on the 26 collapsed runs: median test accuracy 10% as is, 69% with V1c, 74% with V2; the α = 1 control never collapsed (min. 91.4%); the worst forget losses reached 2–3·10⁵ with 68–74% of steps clipped. Diagnostic 2: A diverged in 29 of 30 tasks; B and C in 0 of 30, with test accuracy within about 1.5 points of the original model, but on the forgotten images they stayed closer to O than to R (e.g. class 6: R 79.5%, B 94.5%, C 93.0%). Diagnostic 3: E1 did not diverge on class “Trouser” (0/5 seeds; 92.4–93.3% test accuracy vs 93.0–93.4% for the original model); E1-detached crossed the threshold in 5/5 but peaked at 11–34 instead of about 10⁵; E1-O exploded everywhere, even on class 8. Gradient norms (post hoc): the “keep” and “forget” gradients were nearly orthogonal (no conflict), and the norm jumped about 28 steps after the loss crossed 10: a symptom, not a warning sign.
In plain words
A large part of the disaster was the BatchNorm memory, but not all of it: even repaired, the models sit near 74% instead of 93%, so the weights are damaged too. As soon as the forget batch is no longer normalised on its own (B, C), blow-ups vanish, but so does most of the forgetting.
Does not show
That BatchNorm is the cause: each variant changes several things, the weight was fixed, and later studies found that these variants fail elsewhere (studies 05 and 06).
03Replication v1.3: does it hold with new seeds, and on CIFAR-10?pre-specified, exploratory · 5 + 3 seedsA vs C on all 10 classes and 3 weights
Question
With newly derived seeds, draws and models, are concentrated runs more unstable than spread ones, under A and under C?
Why this study
The diagnostics reused the very runs that revealed the problem. A hypothesis must not be tested on the data that suggested it, so the effect had to be reproduced with new models, under a protocol written in advance, on a second dataset, and with GroupNorm as a control.
Design
Three studies: Fashion-MNIST with BatchNorm (CNN, 5 seeds, the main one), the same CNN with GroupNorm instead of BatchNorm, and CIFAR-10 (ResNet-18, 3 seeds); 10 classes × 3 weights (0.001, 0.01, 0.05); 1,141 runs in 6 hours, 9,801 checks passed. Main statistic: for each seed, the share of the 10 concentrated runs more unstable than the paired spread run of the same seed (a numerical failure counts as more unstable; otherwise the higher mean forget loss). 0.5 means no difference, 1 means always worse. One share per seed, a t test over seeds, Holm correction across the family, and an equivalence test (TOST, margin 1 decade). Protocol committed before the run, but the analysis code was not.
Result
Fashion-MNIST: share 0.86 under A (Holm p = 1.7·10⁻⁵); difference A − C 0.37 (Holm p = 1.5·10⁻⁴). GroupNorm: −0.033, nothing detected, and equivalent to zero by TOST, like C; A was not (concentrated runs 2.39 decades higher). At 0.01, A diverged in 30/50 concentrated runs and collapsed in 24/50; C in 0. CIFAR-10: the share was 1 in all 3 seeds (test not computable), A − C 0.43 (Holm p = 0.0039); A diverged in 60 runs and never collapsed, which shows that divergence and collapse are different things. Spread runs never diverged.
In plain words
The phenomenon is solid and reproducible, and it is tied to batch-dependent normalisation: it disappears with GroupNorm. One doubt remained: always the same six classes.
Does not show
That concentration itself matters: the six classes that diverged were exactly those that had collapsed in v3, so class identity and concentration were still confounded. With 5 and 3 seeds the protocol classifies everything as exploratory.
04NegGrad+ vs random labels, first try: the clipping burdenpre-specified · 10 seeds (5 reused)Is the effect specific to NegGrad+?
Question
Is the concentration effect specific to NegGrad+'s unbounded “push up”, or does it also appear with a bounded objective?
Why this study
If the blow-up comes from NegGrad+'s unbounded push, a bounded objective with everything else identical should suffer much less from concentration.
Design
Both objectives share the original model, forget sets, batch streams, forward passes, BatchNorm treatment and optimiser. The control (RL) teaches labels drawn once among the other classes. Measure: the share of steps whose gradient had to be clipped (threshold 5). Contrast: concentration effect under NG minus under RL, per seed.
Result
At 0.01 the difference was 0.304 (95% CI 0.289–0.318, p < 10⁻¹⁰). But RL sat at the floor: 4 clipped steps in 330 runs.
In plain words
NegGrad+ needs clipping far more often on concentrated sets, but the control could not be judged with this measure.
Does not show
That RL is unaffected: a measure stuck at zero cannot see small effects. This motivated a continuous measure (study 08).
05BatchNorm study v1.0: which part of BatchNorm matters?pre-specified, exploratory · 5 seedsA vs E1 vs E1D, 600 runs
Question
Does the instability come from the gradient flowing through the batch statistics, from the statistics themselves, or from neither?
Why this study
A, B and C differ in several ways at once. To know which part of BatchNorm matters, each variant here changes one ingredient: the gradient path (E1D) or the source of the statistics (E1).
Design
A (own statistics, gradient through them), E1D (own statistics but detached, no buffer update) and E1 (running statistics of retained data). 150 concentrated and 50 spread runs per weight; 600 runs, no numerical failure. Shares the split, classes and weights of v1.3, so it is a follow-up, not an independent replication. Two engineering amendments were committed before the main study.
Result
Divergences on concentrated sets at 0.001 / 0.01 / 0.05: A 12 / 90 / 150, E1D 12 / 89 / 121, E1 0 / 60 / 150 (and E1 diverged in 47/50 spread runs at 0.05). On the optimised forget loss, A was above E1D in 82% of concentrated runs (Holm p = 3.7·10⁻⁵; +0.83 decade), with a gap growing with the weight (+0.01, +0.75, +1.73 decade). That share was 0.33 higher than on spread sets (Holm p = 4.0·10⁻⁴), where the continuous gap was close to zero. E1D vs E1: E1D was above E1 in 65% of concentrated runs (Holm p = 7.5·10⁻⁴), but the continuous gap was +0.04 decade (95% CI −0.08 to 0.16), equivalent to zero within ±1 decade; its larger effect on concentrated sets came mostly from E1 diverging on spread sets at 0.05.
In plain words
Letting the gradient flow through the batch statistics makes things worse, more so as the forget weight grows, but removing it is not a cure.
Does not show
A single mechanism: the results fit a weight-dependent contribution of the gradient through the batch statistics, but E1D and E1 still diverged widely, so that is not the whole story.
06Control of C on CIFAR-10: does freezing BatchNorm cost accuracy?pre-specified, exploratory · 3 seedsResNet-18, 33 cells per weight
Question
C avoided divergence on CIFAR-10. Does it pay for it with accuracy, and is that loss real or an evaluation artefact?
Why this study
C avoided every blow-up, which made it look like a fix, but on CIFAR-10 it cost accuracy. Was that cost real, or an artefact of how C's model was evaluated?
Design
C and E1 on 33 condition × weight cells at 0.001 and 0.01, compared with fine-tuning; evaluation with native and with exactly recalibrated BatchNorm statistics.
Result
C never diverged (0/33 at both weights) but was 1.6–2.9 points below fine-tuning with native statistics; after exact recalibration it was no longer below fine-tuning. E1 diverged in 31/33 cells at 0.01.
In plain words
Most of C's apparent cost came from its stored statistics at evaluation time, not from damaged weights.
Does not show
That C is a remedy: it changes the source of the statistics and the numerical trajectory together, and was tested on one architecture with 3 seeds.
07Concentration beyond class identity: 68 mixespre-specified, exploratory · 10 new seedsThe study that separates concentration from class difficulty
Question
Is the effect due to concentration, or just to some classes being hard?
Why this study
In every study the same six classes diverged. Maybe those classes are simply hard to forget, and “concentrated” only meant “contains a hard class”. This is the objection any reviewer would raise first.
Design
Seeds 401–410, each with its own original model, 68 compositions per seed at n = 600 and weight 0.01: the 10 one-class sets, all 45 two-class sets, 12 five-class sets and the spread set. Outcome: the early forget loss (mean log₁₀ forget loss over steps 0–23), chosen beforehand because it separated later-diverging runs on earlier data (AUC 0.92). Model: per seed, S = log₁₀ Mλ(class proportions; class effects) + γ·H + noise, where Mλ is a power mean of order λ ∈ [−3, 3] and H the label entropy in bits. Test on γ over seeds, with a threshold calibrated by parametric bootstrap (2,000 draws).
Result
γ = −0.246 decade per bit (95% CI −0.263 to −0.228, p = 0.001, all 10 seeds negative; estimated λ between 0.34 and 1.09). Less concentrated sets had a lower early loss than their classes predict, for every combination rule of that family. Under A, 62/100 one-class and 67/450 two-class runs diverged, none with 5 or 10 classes. Under C (secondary), γ = −0.004, equivalent to zero at ±0.075 for the estimated λ but positive with λ fixed at 0.
In plain words
The more concentrated the request, the worse, and not only because some classes are hard. Under C the effect disappears. This is the central result.
Does not show
That no pair of classes interacts in some special way (the model cannot represent that), nor anything about divergence or forgetting directly: the outcome is the early loss level, at one weight and for one model.
08NegGrad+ vs random labels, done properly: a continuous measurepre-specified · 10 new seedsḠ, the mean log size of the gradients before clipping
Question
Same as study 04, with a measure that cannot get stuck at zero.
Why this study
Study 04's measure was stuck at zero under random labels, so it could not show whether they were affected at all.
Design
Seeds 101–110, new models, nothing reused. Ḡ = mean over steps of log₁₀ of the gradient norm before clipping. The analysis was calibrated by Monte Carlo before any run (false-positive rate of the main test 0.044–0.059; Holm family 0.036–0.044). One amendment, on a unit-test tolerance, followed a pilot stop that came before any unlearning run. 782 units; replays bitwise identical.
Result
At 0.01: concentration raised Ḡ by 0.705 decade under NegGrad+ and by 0.053 under random labels; difference 0.652 (95% CI 0.607–0.696, p < 10⁻¹⁰, all 10 seeds). At 0.001 the difference was slightly negative (−0.015); at 0.05 it was 2.644, with the random-label shift negative. Concentrated NG runs lost 1.3, 46.8 and 82.9 test-accuracy points at the three weights, RL only 1.0, 2.0 and 2.9.
In plain words
Concentration makes gradients about 5 times larger under NegGrad+ but only about 13% larger under random labels: a difference of degree, not of kind.
Does not show
That Ḡ measures instability (its direction depends on the weight), nor that random labels are unstable: their small shift never came with divergence.
09Tiny ImageNet: is the signal still there on harder data?pre-specified, exploratory · 5 new seeds200 classes, ResNet-18, one weight
Question
Does the gradient-size signal of study 08 appear outside Fashion-MNIST?
Why this study
Everything so far was on Fashion-MNIST or CIFAR-10 with 10 classes. Does the signal survive on 200 classes and a standard ResNet?
Design
Ten target classes fixed before downloading the archive; for each, a concentrated set of 50 images paired with a spread set (one image of the class and one from each of 49 others). Forget batch of 25, so each forgotten image is seen about 351–352 times in 703 steps; only weight 0.01. An exploratory membership-inference check used the score −loss, with official validation images as non-members.
Result
Contrast θ = 0.0288 decade (95% CI 0.0258–0.0319, p = 1.3·10⁻⁵), positive in all seeds and classes; NG shift 0.0232, random-label shift −0.0056 (detected, but inside the ±0.02 equivalence margin). The divergence criterion was saturated (50/50 in both groups), so it could not separate compositions. Membership-inference AUC: 0.732 original, 0.670 fine-tuning, 0.590 random labels, 0.388 NegGrad+.
In plain words
Same direction on harder data, much smaller in size; the forgotten images became more recognisable as “different”, which an attacker could exploit.
Does not show
Erasure: an AUC below 0.5 means the forgotten images now have a higher loss than unseen ones, an inversion an attacker could exploit. Five seeds, ten classes and one weight do not make a powered replication, and the archive's usage conditions were not verified with its host.
10The source of the statistics alone (v1.2)pre-specified, exploratory · 10 new seedsE1D vs RD64: only where the statistics come from changes
Question
With the gradient path held fixed, does it matter whether the batch to forget is normalised with its own statistics or with those of the concurrent retained batch?
Why this study
Study 05 suggested the gradient path matters. Holding it fixed (both variants detached), does the source of the statistics also matter?
Design
Seeds 411–420, the 68 compositions of study 07. E1D and RD64 both detach the statistics; they differ only in their source. Outcome: capped early loss burden over steps 0–19. Main contrast θ: how much RD64 − E1D changes for mixed sets relative to one-class sets, on the training pass (H1) then on a reference pass (H2). A calibration simulation run before the study showed that a test meant to isolate concentration (Δγ) gave 8.2–19.3% false positives under combination rules outside the family, so it was withdrawn and reported only descriptively. One amendment (a unit-check tolerance) after a pilot stop that came before any task.
Result
θ = 0.670 decade (95% CI 0.632–0.708) on the training pass and 0.210 (0.187–0.232) on the reference pass, positive in all seeds. Mostly because RD64 lowered the early loss of one-class sets (by 0.79 decade; 0.31 for pairs, 0.06 for five classes, 0 for the spread set). No RD64 run diverged or collapsed (0/680), against 61/100 one-class and 53/450 two-class E1D divergences.
In plain words
Giving the forget batch “normal” statistics instead of its one-class ones calms almost everything, mostly for one-class sets.
Does not show
A concentration-specific effect or a mechanism: the comparison does not separate the source of the statistics from the mismatch between the batch and the statistics used.
11A frozen alternative target (CF)pre-specified · 12 new seedsReplace the unbounded push with a bounded target
Question
If NegGrad+ fails because its push is unbounded, does descending towards a fixed, sensible target avoid the concentration penalty?
Why this study
Attack suspect n°1, the unbounded objective, while keeping BatchNorm as in A.
Design
For each forgotten (x, y), the target is the original model's softmax over the classes other than y (true class masked before the softmax). NG at weights 0.01 and 0.05, RL and CF at 0.01, 0.05 and 0.2; seeds 421–432. Outcome U: accuracy loss on the retained data, after recalibrating BatchNorm on that data. Two main tests with Holm correction. The draft planned 10 seeds; the power simulation gave 0.72 (below 0.80), so 12 seeds were fixed before the freeze (0.81). One amendment: a unit test compared logits computed with different batch sizes, which differ under the A100's TF32 arithmetic. 1,467 units, replays bitwise identical.
Result
Interaction NG vs CF: 16.2 points (95% CI 14.1–18.4, Holm p = 7·10⁻⁹), all 12 seeds. RL vs CF: −0.02 (no difference detected; no equivalence test planned). CF's own penalty 0.25 point, detected but inside ±2 points. NG collapsed in 70/120 concentrated runs at 0.01 and 117/120 at 0.05; RL and CF never.
In plain words
It damages much less, but it barely forgets: “safe” mostly because it does little.
Does not show
Successful forgetting: the force check rested on a nearly null reference (NG force 0.019 decade, CF 0.051), and on concentrated sets CF left the accuracy on the forgotten images at 96.7–97.4% (fine-tuning 98.2%), even though it fitted its targets during training.
12A bundled BatchNorm fix (RD64)pre-specified · 14 new seedsNormalise the batch to forget with retained-batch statistics
Question
Does the RD64 treatment, which never diverged in study 10, reduce the concentration penalty on retained utility?
Why this study
Attack suspect n°2: apply to NegGrad+ the RD64 treatment that never diverged in study 10, and see whether the accuracy penalty disappears too.
Design
At each BatchNorm layer, the batch to forget uses the mean and variance of the first 64 rows of the retained batch of the same step, detached, without updating the stored statistics. So three things change at once: the source of the statistics, the gradient path and the buffer updates. Seeds 433–446. Single test on I = penalty(A) − penalty(RD64). Power planned for a negative correlation between the two penalties: 12 seeds gave 0.737, 14 gave 0.818–0.872. No amendment.
Result
I = 13.7 points (95% CI 12.6–14.7, p = 4·10⁻¹³), positive in all 14 seeds (10.7–17.1). NG-A: 84/140 divergences and 75/140 collapses; NG-RD: 0 and 0. Accuracy on the concentrated forget sets (recalibrated): 80.2% NG-A, 96.7% NG-RD, 98.5% fine-tuning, 93.1% retrained.
In plain words
It prevents every blow-up in every seed, but we do not know which of its three changes does the work, and it forgets about as little as fine-tuning.
Does not show
Which of the three changes matters, or forgetting: NG-RD's forgetting strength was about 0.03 decade, and its predictions on the forgotten images barely moved away from fine-tuning (1.7 points).
13Per-class tuning: does a good setting suffice?pre-specified · 3 + 12 new seeds20 settings per class, chosen by a fixed rule
Question
Maybe NegGrad+ was simply badly tuned for concentrated requests. Does the penalty survive when the learning rate and the forget weight are chosen separately for each class?
Why this study
Rule out the simplest explanation: maybe nothing is wrong with NegGrad+ and the default setting was just bad for concentrated requests.
Design
Tuning seeds 447–449: grid of 4 learning rates (0.001–0.03) × 5 weights (0.001–0.05). A setting is stable if no run failed, diverged or collapsed, and feasible if it also reaches the forgetting strength of the retrained model. Rule: the feasible setting with the best validation accuracy, else the strongest stable one; it never sees test data or evaluation seeds, and the analysis recomputed it identically. Evaluation seeds 450–461 (12, fixed by power simulation): chosen setting vs the default 0.01/0.01. Main test plus a ±2-point equivalence test. Ran in two Colab sessions (A100 40 GB, then 80 GB).
Result
Penalty with tuning 1.07 points (95% CI 0.88–1.27), equivalent to zero within ±2; with the default setting 14.2. Divergences on concentrated sets 2/120 vs 71/120. But only 3 of 10 classes had a feasible setting; spread requests were stable under all 20 settings, concentrated ones under 1 to 16.
In plain words
Tuning removes most of the penalty, but for 7 of 10 classes only by pushing less hard than retraining would require.
Does not show
An equal-strength comparison: for 7 classes the chosen setting acted less than the retrained model, and on the evaluation seeds the retrained strength was reached in only 20% of concentrated runs (67% of spread runs).

Appendix · How it was done

It began with an unexpected failure, continued with exploratory diagnostics, and then moved to studies whose plan was fixed before any result was seen:

  • Protocol: the question, one main test and the wording of each possible conclusion.
  • Simulations: how many seeds are needed (power), and whether the test raises false alarms (calibration).
  • Freeze: the plan and the code are committed with a fingerprint before the run.
  • Pilot: only to measure computing time; its results stay sealed.
  • Study and frozen analysis: run on a cloud GPU (A100), analysed exactly as written.

Each seed trains a new model, and the statistics treat one seed as one data point. The studies share some data, so they are not fully independent replications, and the plans live in a private repository rather than a public registry.

When something went wrong

Three times (studies 08, 10 and 11) a pilot stopped on a blocking unit test before any unlearning run; in the last two the tolerance was too strict for the A100's reduced-precision (TF32) arithmetic. Each time the fix was written as a dated amendment, committed, and the pilot re-run; no result had been looked at. The notebooks also stop on their own if, for example, the code fingerprint differs from the frozen one, or if a replayed run is not bit-for-bit identical.

Appendix · How the results were checked

Before writing anything up, I audited the four most recent studies end to end:

  • Code: the code executed on the GPU had the same fingerprint as the frozen, committed notebook, in all four studies; no blocking check failed.
  • Analyses: six frozen analyses were re-run from the raw per-run tables and reproduced their committed outputs exactly.
  • Numbers: 52 key numbers quoted in the write-up were recomputed independently from the raw tables, without the analysis scripts; all matched up to rounding, and the tuning rule recomputed from scratch chose the same settings.
  • One correction: the audit showed that most “collapses” disappeared after recomputing BatchNorm statistics (section 5), so the wording of the write-up was corrected.
  • Not checkable: the raw Tiny ImageNet tables are not in the repository, and the original study has no recalibrated evaluation.
